Étape 1
Initialisation du projet
Lance ces commandes dans ton terminal VS Code, dans l'ordre, pour créer la base du projet.
1
Créer le projet React + Vite + TypeScript
Dans le terminal : npm create vite@latest smartmarket -- --template react-ts puis cd smartmarket
2
Installer les dépendances
npm install puis npm install @supabase/supabase-js react-router-dom react-hook-form zustand lucide-react
3
Installer Tailwind CSS
npm install -D tailwindcss postcss autoprefixer puis npx tailwindcss init -p
4
Créer le projet Supabase
Va sur supabase.com, crée un nouveau projet "smartmarket", copie l'URL et la clé anon dans ton .env
5
Lancer le dev server
npm run dev — l'app tourne sur http://localhost:5173

-- ============================================
-- SMARTMARKET — Schéma Phase 1
-- ============================================

-- 1. PROFILS UTILISATEURS (extension de auth.users)
CREATE TABLE profiles (
  id          UUID PRIMARY KEY REFERENCES auth.users(id) ON DELETE CASCADE,
  full_name   TEXT NOT NULL,
  phone       TEXT,
  role        TEXT CHECK(role IN ('buyer', 'seller')) DEFAULT 'buyer',
  avatar_url  TEXT,
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- 2. BOUTIQUES VENDEURS
CREATE TABLE shops (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  owner_id    UUID REFERENCES profiles(id) ON DELETE CASCADE,
  name        TEXT NOT NULL,
  description TEXT,
  commune     TEXT,
  whatsapp    TEXT,
  logo_url    TEXT,
  status      TEXT CHECK(status IN ('pending', 'active', 'suspended'))
              DEFAULT 'pending',
  created_at  TIMESTAMPTZ DEFAULT NOW()
);

-- 3. RAYONS / CATÉGORIES (données fixes)
CREATE TABLE categories (
  id    SERIAL PRIMARY KEY,
  name  TEXT NOT NULL,
  emoji TEXT,
  slug  TEXT UNIQUE NOT NULL
);

-- Insertion des 6 rayons Smartmarket
INSERT INTO categories (name, emoji, slug) VALUES
  ('Légumes frais',       '🥬', 'legumes-frais'),
  ('Épices & condiments', '🌿', 'epices-condiments'),
  ('Conserves & secs',    '🥫', 'conserves-secs'),
  ('Tubercules',          '🍠', 'tubercules'),
  ('Herbes aromatiques',  '🌱', 'herbes-aromatiques'),
  ('Maraîchers divers',   '🧅', 'maraichers-divers');

-- 4. PRODUITS
CREATE TABLE products (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  shop_id      UUID REFERENCES shops(id) ON DELETE CASCADE,
  category_id  INT  REFERENCES categories(id),
  name         TEXT NOT NULL,
  description  TEXT,
  price        INTEGER NOT NULL, -- Prix en FCFA
  unit         TEXT CHECK(unit IN ('kg','sachet','botte','pièce','litre')),
  in_stock     BOOLEAN DEFAULT TRUE,
  status       TEXT CHECK(status IN ('draft','published')) DEFAULT 'draft',
  created_at   TIMESTAMPTZ DEFAULT NOW()
);

-- 5. PHOTOS PRODUITS
CREATE TABLE product_images (
  id         UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  product_id UUID REFERENCES products(id) ON DELETE CASCADE,
  url        TEXT NOT NULL,
  position   INT  DEFAULT 0
);

-- ============================================
-- ROW LEVEL SECURITY (RLS)
-- ============================================

ALTER TABLE profiles      ENABLE ROW LEVEL SECURITY;
ALTER TABLE shops         ENABLE ROW LEVEL SECURITY;
ALTER TABLE products      ENABLE ROW LEVEL SECURITY;
ALTER TABLE product_images ENABLE ROW LEVEL SECURITY;

-- profiles : lecture publique, écriture = owner
CREATE POLICY "profiles_select" ON profiles FOR SELECT USING (TRUE);
CREATE POLICY "profiles_update" ON profiles FOR UPDATE USING (auth.uid() = id);
CREATE POLICY "profiles_insert" ON profiles FOR INSERT WITH CHECK (auth.uid() = id);

-- shops : lecture si active, écriture = owner
CREATE POLICY "shops_select" ON shops
  FOR SELECT USING (status = 'active' OR owner_id = auth.uid());
CREATE POLICY "shops_insert" ON shops
  FOR INSERT WITH CHECK (owner_id = auth.uid());
CREATE POLICY "shops_update" ON shops
  FOR UPDATE USING (owner_id = auth.uid());

-- products : lecture si published, écriture = shop owner
CREATE POLICY "products_select" ON products
  FOR SELECT USING (
    status = 'published'
    OR shop_id IN (SELECT id FROM shops WHERE owner_id = auth.uid())
  );
CREATE POLICY "products_insert" ON products
  FOR INSERT WITH CHECK (
    shop_id IN (SELECT id FROM shops WHERE owner_id = auth.uid())
  );
CREATE POLICY "products_update" ON products
  FOR UPDATE USING (
    shop_id IN (SELECT id FROM shops WHERE owner_id = auth.uid())
  );

-- product_images : même logique que products
CREATE POLICY "images_select" ON product_images
  FOR SELECT USING (
    product_id IN (SELECT id FROM products WHERE status = 'published')
    OR product_id IN (
      SELECT p.id FROM products p
      JOIN shops s ON s.id = p.shop_id
      WHERE s.owner_id = auth.uid()
    )
  );
CREATE POLICY "images_insert" ON product_images
  FOR INSERT WITH CHECK (
    product_id IN (
      SELECT p.id FROM products p
      JOIN shops s ON s.id = p.shop_id
      WHERE s.owner_id = auth.uid()
    )
  );

-- ============================================
-- STORAGE BUCKET (photos produits)
-- ============================================
INSERT INTO storage.buckets (id, name, public) VALUES
  ('product-images', 'product-images', TRUE);

-- Trigger : créer un profil automatiquement à l'inscription
CREATE OR REPLACE FUNCTION handle_new_user()
RETURNS TRIGGER AS $$
BEGIN
  INSERT INTO profiles (id, full_name, phone)
  VALUES (
    NEW.id,
    COALESCE(NEW.raw_user_meta_data->>>'full_name', ''),
    NEW.phone
  );
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;

CREATE TRIGGER on_auth_user_created
  AFTER INSERT ON auth.users
  FOR EACH ROW EXECUTE FUNCTION handle_new_user();

====================================================
SMARTMARKET — Prompt Bootstrap Phase 1
====================================================

Tu es un développeur React/TypeScript senior.
Tu vas m'aider à construire Smartmarket, une marketplace
mobile-first de produits alimentaires frais (légumes, épices,
conserves, maraîchers) pour le marché ivoirien (Abidjan).

## STACK TECHNIQUE
- React 18 + Vite + TypeScript
- Tailwind CSS (utilitaires uniquement)
- Supabase (Auth + PostgreSQL + Storage)
- React Router v6
- React Hook Form (formulaires)
- Zustand (state global)
- Lucide React (icônes)

## CHARTE VISUELLE
- Couleur primaire : #16A34A (vert)
- Couleur accent   : #EA580C (orange)
- Style : mobile-first, cards arrondies (rounded-2xl),
  ombres légères, photos produits plein format
- Police : system-ui (pas de Google Fonts pour le MVP)
- Inspiré de l'app Fourmis Food (marché ivoirien)

## DEUX TYPES D'UTILISATEURS

1. ACHETEUR (role = 'buyer')
   → Browse les rayons et les produits
   → Consulte les fiches produits
   → (panier et commande = Phase 2)

2. VENDEUR (role = 'seller')
   → Crée sa boutique à l'inscription
   → Publie et gère ses produits par rayon
   → Dashboard avec liste de ses produits

## AUTHENTIFICATION

Deux méthodes au choix à l'inscription :
- Email + mot de passe (Supabase emailAuth)
- Téléphone + OTP SMS (Supabase phoneAuth)

À la connexion : même choix email ou téléphone.
Mot de passe oublié via email ou SMS.

Après inscription, l'utilisateur choisit son rôle.
Si rôle = 'seller', il remplit un formulaire boutique.

## PAGES À GÉNÉRER (10 pages)

### PAGE 1 : /onboarding
- 3 slides défilables (swipe ou boutons)
- Slide 1 : "Votre marché local, livré chez vous"
- Slide 2 : "Vendeurs locaux vérifiés"
- Slide 3 : "100% Frais, Prix marché"
- Bouton "Commencer" → /register

### PAGE 2 : /register
Formulaire d'inscription :
- Champ : Prénom + Nom (obligatoire)
- Champ : Email OU Numéro de téléphone (au choix, obligatoire)
- Si téléphone → format +225XXXXXXXXXX avec indicatif Côte d'Ivoire
- Mot de passe + confirmation (min 6 car)
- Bouton "Créer mon compte" → appel Supabase signUp
- Lien "J'ai déjà un compte" → /login

### PAGE 3 : /register/role
Après inscription réussie, choix du rôle :
- Deux grandes cartes cliquables :
  Card 1 : 🛒 "Je veux acheter" → role = 'buyer' → /home
  Card 2 : 🏪 "Je veux vendre" → role = 'seller' → /register/shop

### PAGE 4 : /register/shop
Formulaire boutique vendeur (obligatoire avant de publier) :
- Nom de la boutique (obligatoire)
- Description courte (max 200 car, optionnel)
- Commune (liste déroulante) :
  Abobo, Adjamé, Attécoubé, Cocody, Koumassi,
  Marcory, Plateau, Port-Bouët, Treichville, Yopougon
- Numéro WhatsApp de contact
- Photo logo boutique (upload vers Supabase Storage)
- Statut boutique par défaut : 'pending' (admin valide)
- Message affiché : "Votre boutique est en cours de validation (24-48h)"
- Bouton "Enregistrer ma boutique" → /seller/dashboard

### PAGE 5 : /login
- Choix : connexion par email OU téléphone (tabs)
- Email : email + password
- Téléphone : numéro + OTP SMS (Supabase sendOtp)
- Bouton "Se connecter" → redirect selon role (buyer→/home, seller→/seller/dashboard)
- Lien "Mot de passe oublié"
- Lien "Créer un compte"

### PAGE 6 : /home (Acheteur)
Header : logo Smartmarket + barre de recherche (décorative Phase 1) + icône panier
Section rayons : grille 3 colonnes, 6 cards de rayons avec emoji + nom
Section "Produits récents" : grille 2 colonnes de ProductCard
Bottom navigation : Accueil | Rayons | Panier | Menu

### PAGE 7 : /category/:slug (Acheteur)
- Header avec flèche retour + nom du rayon
- Grille de ProductCard filtrés par category_id
- État vide élégant si pas de produits

### PAGE 8 : /product/:id (Acheteur)
- Photo(s) produit en carousel (si plusieurs images)
- Nom, prix en FCFA, unité, badge stock
- Description (si présente)
- Nom de la boutique + commune vendeur
- Bouton WhatsApp "Contacter le vendeur" (lien wa.me)
- Phase 2 : bouton "Ajouter au panier"

### PAGE 9 : /seller/dashboard (Vendeur)
- Header : "Mes produits" + bouton "+ Ajouter un produit"
- Statut boutique visible (pending/active)
- Liste des produits du vendeur en cards :
  Chaque card : photo | nom | prix | statut (brouillon/publié) | bouton éditer
- Filtre : Tous / Publiés / Brouillons
- État vide avec CTA "Ajouter votre premier produit"

### PAGE 10 : /seller/product/new et /seller/product/:id/edit (Vendeur)
Formulaire complet :
- Nom du produit (obligatoire)
- Rayon (select avec 6 options, obligatoire)
- Description (textarea, optionnel)
- Prix en FCFA (number, obligatoire, min 0)
- Unité : kg / sachet / botte / pièce / litre (select)
- En stock : toggle switch oui/non
- Photos : upload 1 à 3 photos vers Supabase Storage bucket 'product-images'
  → Compression client avant upload (max 800px, qualité 0.8)
  → Preview des photos sélectionnées
- Statut : Brouillon / Publié (boutons radio)
- Contraintes : vendeur doit avoir boutique 'active' pour publier
- Bouton "Enregistrer" + bouton "Supprimer" (si édition)

## COMPOSANTS À CRÉER

ProductCard.tsx :
- Props : product (Product), onClick
- Photo principale ou placeholder vert
- Nom produit (tronqué à 2 lignes)
- Prix en FCFA (formaté : "1 500 FCFA")
- Badge unité (ex: "/ kg")
- Badge stock si rupture

BottomNav.tsx :
- 4 onglets : Accueil (Home), Rayons (Grid2x2), Panier (ShoppingCart), Menu (Menu)
- Onglet actif : couleur verte #16A34A
- Fixed au bas de l'écran

ProtectedRoute.tsx :
- Vérifie que l'utilisateur est connecté via Zustand authStore
- Redirige vers /login si non connecté

## STATE MANAGEMENT (Zustand)

authStore.ts :
- state : { user, profile, session, loading }
- actions : setUser, setProfile, logout
- Init : supabase.auth.onAuthStateChange()
  → sur SIGNED_IN : fetch profile depuis table profiles

shopStore.ts :
- state : { shop, loading }
- actions : setShop, fetchShop(userId)

## ROUTING (App.tsx)

Routes publiques :
  / → Onboarding (si pas de session) ou Home (si session + buyer)
  /login → Login
  /register → Register
  /register/role → RegisterRole
  /register/shop → RegisterShop (nécessite session)
  /category/:slug → CategoryPage
  /product/:id → ProductDetail

Routes protégées (ProtectedRoute) :
  /home → Home (buyers)
  /seller/dashboard → SellerDashboard (sellers uniquement)
  /seller/product/new → AddProduct
  /seller/product/:id/edit → AddProduct (mode édition)

## UPLOAD PHOTOS (Supabase Storage)

Fonction utilitaire à créer dans lib/supabase.ts :
async function uploadProductImage(file: File, productId: string): Promise
  1. Redimensionner l'image côté client (Canvas API, max 800px, qualité 0.8)
  2. Nommer le fichier : products/{productId}/{timestamp}.jpg
  3. Upload vers bucket 'product-images' (public)
  4. Retourner l'URL publique

## RÈGLES MÉTIER IMPORTANTES

1. Un vendeur ne peut publier de produit que si shop.status = 'active'
   → Si 'pending' : afficher message "En attente de validation"
   → Si 'suspended' : afficher message "Boutique suspendue"

2. Maximum 50 produits par vendeur pour le MVP

3. Les catégories sont en lecture seule (insertées via SQL)

4. Lors de la navigation vers /home :
   → Si pas de session → /onboarding
   → Si session + role = 'seller' → /seller/dashboard
   → Si session + role = 'buyer' → /home
